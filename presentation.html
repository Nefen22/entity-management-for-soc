01. Đặt Vấn Đề

Tại Sao Điều Tra SOC Truyền Thống Khó Khăn?

Operational Pain

Thách thức của SOC: Sự cô lập và phi cấu trúc của dữ liệu log khiến việc điều tra lateral movement gặp nhiều trở ngại.

Sự Cô Lập Của Log

Log từ SIEM, EDR, Cloud lưu ở nhiều nơi với cấu trúc khác nhau. Nhà phân tích phải truy vấn thủ công, làm tăng MTTR.

Cảnh Báo Dạng Tự Do

Alerts dạng free-text từ các nguồn Threat Intelligence không có cấu trúc cố định, khiến parser truyền thống thất bại.

Đồ Thị Hóa Quan Hệ

Chuyển từ lưu trữ tài liệu sang mô hình hóa thực thể. Sử dụng Neo4j để xâu chuỗi sự kiện và liên kết quan hệ tự động.

02. Mục Tiêu

Ba Mục Tiêu Cốt Lõi Của Đề Tài

Objectives

Định hướng giải quyết: Xây dựng hệ thống tự động hóa chuẩn hóa dữ liệu bảo mật và nâng cao hiệu quả điều tra của analyst.

1. Ingest Đa Nguồn Dữ Liệu

Hỗ trợ tiếp nhận và tiền xử lý log từ nhiều nguồn như SIEM, EDR, Cloud logs và cả các cảnh báo dạng tự do.

2. Tự Động Xây Dựng Entity Graph

Trích xuất thực thể (User, Host, IP, File Hash) và tự động thiết lập mối quan hệ từ cả log cấu trúc và phi cấu trúc.

3. Hỗ Trợ Điều Tra Trực Quan

Cung cấp tính năng Graph Visualization, Path Finding tìm lateral movement, làm giàu dữ liệu và RBAC.

Tính Năng Relational / Document JOIN Entity Graph (Neo4j)
Độ trễ truy vết Tăng theo cấp số nhân khi đi sâu đa bước (O(N\log N)) Đo lường O(1) qua con trỏ bộ nhớ trực tiếp
Độ phức tạp câu lệnh Nhiều tầng JOIN lồng nhau (SQL) hoặc lookup phức tạp Cypher cực kỳ đơn giản:
(u:User)-[*..3]->(ip:IP)
Tích hợp thông tin Cần định nghĩa trường cứng hoặc cấu trúc nested phức tạp Lưu linh hoạt thuộc tính trên Node và Edge, hỗ trợ Path Finding

03. Kiến Trúc

Tại Sao Thiết Kế Hệ Thống Đa Cơ Sở Dữ Liệu?

Multi-DB Linkage

Lưu trữ phân tách: Kết hợp thế mạnh của từng công nghệ CSDL để lưu trữ tối ưu cả cấu trúc đồ thị lẫn bằng chứng logs nguyên bản.

Neo4j: Tối ưu hóa traversal

Chịu trách nhiệm lưu trữ và truy vấn cấu trúc đồ thị an ninh mạng. Giải quyết bài toán Path Finding và truy vết mối quan hệ.

MongoDB: Lưu trữ Raw Event & Audit Log

Lưu trữ nguyên bản log thô JSON đa dạng và ghi lịch sử chỉnh sửa đồ thị (CREATE/UPDATE diffs) mà không gây phình to đồ thị Neo4j.

Redis: Caching cho Enrichment

Lưu trữ đệm kết quả làm giàu dữ liệu thực thể từ VirusTotal, AbuseIPDB với TTL 3600s để bảo vệ API rate limits.

04. Pipeline Ingest

Tại Sao Thiết Kế Pipeline Ingest 3 Tầng?

Triage Priority

Dự phòng linh hoạt: Đảm bảo hệ thống hoạt động liên tục ngay cả khi dịch vụ trí tuệ nhân tạo (AI) bên ngoài gặp sự cố hoặc nghẽn mạng.

JSON Parser (Core - Ưu tiên 1)

Xử lý log có cấu trúc (SIEM/EDR/Cloud) qua mapping tĩnh. Tốc độ cực cao, chi phí tính toán bằng 0.

LLM Normalizer (AI Fallback - Ưu tiên 2)

Fallback khi log không đúng định dạng chuẩn. Chuẩn hóa log tự do sang Canonical Event qua Gemini API.

Regex Parser (Safety Fallback - Ưu tiên 3)

Lá chắn cuối cùng. Trích xuất trực tiếp IOC thô bằng regex khi API AI quá tải hoặc lỗi kết nối.

05. Tích Hợp AI & Toàn Vẹn Dữ Liệu

Cơ Chế Placeholder Encoding & Canonical Event

Integrity Control

Bảo vệ dữ liệu an ninh: Sử dụng AI một cách thông minh bằng cách giới hạn nhiệm vụ và kiểm soát dữ liệu đầu vào/đầu ra.

Placeholder Encoding (Bảo vệ IOC)

Mã hóa các thực thể quan trọng (IP, URL, Hash) thành các token dạng <ips_0> trước khi gửi cho LLM. Triệt tiêu hallucination và chống AI tự ý sửa đổi.

Canonical Event (Chuẩn hóa trung gian)

LLM chỉ làm nhiệm vụ đọc ngữ nghĩa văn bản và đưa về Canonical JSON schema chung. AI không trực tiếp vẽ node hay thiết lập mối quan hệ trên graph.

Thống Nhất Pipeline Xử Lý Phía Sau

Khôi phục IOC gốc từ placeholder, đưa Canonical Event qua JSON Parser cốt lõi để vẽ graph. Giúp toàn hệ thống chỉ cần duy trì một Graph Builder.

Placeholder Encoding Flow

Input: "Outbound to 185.220.101.45"
➔ Tách IPv4 bằng Regex cục bộ: 185.220.101.45
To LLM: "Outbound to <ips_0>"
➔ LLM phân tích và trả về Canonical JSON
Restore & Ingest: Khôi phục 185.220.101.45 nạp JSON Parser ➔ Neo4j

06. Điều Tra Trên Graph

Chức Năng Hỗ Trợ Điều Tra Trên Đồ Thị

Triage Features

Công cụ tối ưu triage: Giao diện trực quan hóa Cytoscape kết hợp kiểm soát phân quyền API nghiêm ngặt và Audit Log đầy đủ.

Xác thực JWT & Phân quyền RBAC

Quyền Analyst chỉ được xem đồ thị và làm giàu thực thể. Quyền Admin mới được phép upload và ingest log mới.

Graph Explorer (Cytoscape.js)

Hỗ trợ tương tác trực quan, chạy thuật toán Path Finding tìm đường đi ngắn nhất để truy vết lateral movement.

Audit Log & Cache Làm Giàu

Ghi nhận thay đổi (diff Before/After) vào MongoDB. Redis cache kết quả enrichment (VirusTotal, AbuseIPDB) với TTL 1h.

07. Demo Trực Tiếp

Kịch Bản Demo Các Tình Huống Thực Tế

Live Demo

Kiểm chứng tính năng: Minh họa khả năng xử lý đa nguồn dữ liệu và giao diện điều tra trực quan.

1. Ingest Log JSON Có Cấu Trúc

Tải file log JSON mẫu (SIEM, EDR). JSON Parser sẽ tự động trích xuất các Entity và tạo graph trên Neo4j theo schema mapping.

2. Ingest Free Text (LLM Normalizer)

Nhập tay một ghi chú điều tra (unstructured incident note). Kích hoạt Placeholder Encoding -> LLM -> Canonical Event -> JSON Parser.

3. Analyst Investigation

Tìm kiếm thực thể, mở rộng đồ thị, thực hiện làm giàu (enrichment IP), kiểm chứng Redis cache, và chạy tìm đường đi (Path Finding).

09. Hạn Chế & Hướng Phát Triển

Hạn Chế Hiện Tại & Lộ Trình Phát Triển

Roadmap

Lộ trình nâng cấp: Hoàn thiện hệ thống bằng cách tăng tính tự chủ bảo mật của AI và thiết kế cơ chế xử lý hàng đợi bất đồng bộ.

Hạn Chế Hiện Tại

  • Mối quan hệ tĩnh theo schema mapping, chưa mô hình hóa event type đầy đủ ngữ nghĩa.
  • Chưa có cơ chế Entity Resolution để hợp nhất thực thể trùng lặp.
  • Chưa tích hợp sẵn Correlation Engine tự động phát hiện chuỗi tấn công.

Hướng Phát Triển

  • Bổ sung Event Taxonomy/Semantic Layer tăng độ chính xác của relationship.
  • Xây dựng cơ chế Entity Resolution hợp nhất các thực thể tương đương.
  • Tích hợp Kafka xử lý stream log tải lớn và bổ sung Correlation Engine.
